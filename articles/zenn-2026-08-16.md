![Mermaid風のテキストから図解を生成するGridgram](https://notes.ideamans.com/ogp/2026/gridgram-concept.jpg)

業務では、物事の関係図や概念図、いわゆるポンチ絵を作る場面がよくあります。PowerPointやKeynote上でマウスを使ってチクチク作ると、案外手間と時間がかかるものです。構造は数分で頭に浮かんでいます。それでも絵にする作業だけで30分や1時間が溶けることは珍しくありません。

文章やプログラムはAIで生成できるようになった今でも、図の生成にはまだ少し手間を感じます。コードやテキストの生産性は上がったのに、図についてはぴったりのソリューションがまだない、というのが弊社（アイデアマンズ）の実感でした。

そこでテキストDSL（`.gg` ファイル）からSVGとPNGを生成するCLIツール Gridgram を作り、オープンソースで公開しました。この記事では、なぜ作ったのかと、記法の設計をどう考えたのかを紹介します。

- リポジトリ: https://github.com/ideamans/gridgram
- ドキュメント: https://gridgram.ideamans.com/

## Figures as Code への関心と既存ツールの物足りなさ

コードで図を書くというアプローチにはかねてから関心がありました。IaC（Infrastructure as Code）をもじって Figures as Code と呼んでいます。最初はGraphViz、次にMermaid、最近はD2を本格的に使ってきました。

一方で、既存のテキストDSL系を業務資料に使おうとすると気になる点がありました。MermaidやGraphViz、D2はグラフが横または縦に延々と伸びやすいのです。フローが長くなると画面からはみ出し、「このスペースに収める」という制御が難しくなります。プレゼンの1スライドや提案書の1枠に収めたいのに、試行錯誤が要ります。見た目もテキスト出身で味気なく、提案資料に載せると寂しい印象になりがちでした。

かといって画像生成AIは表現力が高い反面、細かいレイアウト調整が難しく、再現性も高くありません。統一感を保ちにくく、仕様書に載せるとドラマチックすぎて浮いてしまうこともあります。

つまり決定論的に生成でき、かつ寂しすぎない見た目を両立するツールが見当たりませんでした。それがGridgramを作った背景です。

## 発想：まずグリッドに配置する

Gridgramの出発点は、まずオブジェクトをExcel風のマス目（グリッド）へ配置するところにあります。

ユーザーは各ノードをA1・B2のようなセル座標で置きます。そのうえで矢印やラベルをテキストで定義すると、グリッドの隙間を決定論的なアルゴリズムで埋めるように、互いの衝突を避けながら自動配置されます。

この発想の利点は、描画空間（アスペクト比）を先に決められることです。たとえば「4列2行のグリッドに収める」と決めれば、2対1の画角で出力が得られます。Mermaidのように「気付いたら横や縦に延びすぎていた」という事態が起きません。

そのうえで6000種類以上のオープンソースアイコンライブラリ Tabler Icons を組み込んでいるので、テキストだけでなくアイコンで視覚的に装飾でき、寂しくない見た目を作れます。

## .ggファイルの文法

記法はMermaidに似せてあります。`.gg` 拡張子のテキストファイルに書きます。

```text:flow.gg
doc {
  cols: 4,
  theme: { primary: '#0369a1', secondary: '#0891b2', accent: '#f59e0b' },
}

region @A1:B2 "作成・編集"   color=accent/20
region @C1:C2 "変換"         color=secondary/20
region @D1:D2 "生成物"       color=primary/20

icon :user    @A1 tabler/user          "ユーザー"
icon :agent   @B1 tabler/robot         "AIエージェント"
icon :editor  @A2 tabler/pencil        "テキストエディタ"
icon :ggfile  @B2 tabler/file-code     ".ggファイル"
icon :ggcmd   @C1 tabler/terminal      "ggコマンド"
icon :svg     @D1 tabler/vector        "SVG"
icon :png     @D2 tabler/photo         "PNG"

user   --> agent   "依頼"
agent  --> ggfile  "生成"
editor --> ggfile  "直接編集"
ggfile --> ggcmd   "入力"
ggcmd  --> svg     "出力"
ggcmd  --> png     "出力"
```

`doc { cols: N }` でグリッドの列数を決めます。`icon` でノードをセル座標に置き、`-->` でコネクタを引くと、矢印はグリッドの隙間を自動でルーティングされます。リージョンの色は `color=accent/20`（透明度20%のアクセントカラー）のように指定します。

この `.gg` ファイルを `gg` コマンドに渡すと、次のようにSVGとPNGを出力できます。

```bash
gg flow.gg -o flow.svg
gg flow.gg -o flow.png --width 1200
```

出力される図が、こちらです。`cols: 4` を指定してあるので、横に伸びすぎることなく4列のグリッドにきちんと収まっています。

## アイコンを探す

図に添えるアイコンは、6000種類以上のTabler Iconsから検索できます。キーワードやタグで絞り込めるので、思い描いた概念に近いアイコンをコマンド1つで見つけられます。

```bash
# キーワードで検索
gg icons --search database --limit 10

# タグで絞り込む
gg icons --tag cloud --limit 15
```

## 導入方法

`gg` コマンドは自己完結した単一バイナリで、GitHub Releases から入手します。npmのインストールは要りません。

- [Releases · ideamans/gridgram](https://github.com/ideamans/gridgram/releases)

ライブラリとしてアプリケーションに組み込む場合は、npmパッケージも公開しています。こちらはESM環境が前提です。

```bash
npm install gridgram
```

なおPNG出力はCLI専用で、内部で libvips に依存します。バイナリには同梱しておらず、初回のPNG生成時に sharp とプリビルドの libvips が `~/.cache/gridgram/` へ取得され、動的に読み込まれます（LGPLのライブラリを差し替え可能に保つためです）。

## まとめ

Gridgramは「スペースを先に決めてから図を描く」という発想をテキストDSLで実現するツールです。グリッドに収まる決定論的な出力、6000種類以上のアイコン、Mermaidライクなシンプルな記法を組み合わせています。

コードとして図を管理できるので、差分をレビューしたり、AIエージェントに書かせたりといった運用にも乗せやすい設計にしています。プレゼン資料や提案書に載せる図の作成に手間を感じている方は、一度試してみてください。
