長く使ってきたサービスから乗り換えるとき、最後に立ちはだかるのが「溜めたデータをどう持ち出すか」です。

RSSリーダーのFeedlyには長らくお世話になり、有料のProプランも使ってきました。UIは今でも使いやすいと思っています。ただ、APIがEnterpriseプランでしか使えません。ブックマークした記事をAIでもっと活用したいのに、その入口がないわけです。

そこで別のサービスへの移行に着手したのですが、少なくとも「あとで読む」に溜めた記事は持っていきたい。Web GUIしか手段がない状況で、どう取り出したかを共有します。同じ状況は他のサービスでも起こり得るはずです。

## 方針: 画面に出ているものはDOMにある

エクスポート機能はなく、APIも開放されていない。それでも、画面に表示されている以上、そのデータはDOMの中にあります。

ChromeのDevToolsにはJavaScriptコンソールがあり、開いているページに対してその場でスクリプトを実行できます。DOMを走査してテキストへ組み立て、クリップボードに流し込めば、表計算ソフトへ貼り付けられる形になります。

最近はこの手のスクリプトをAIが書いてくれるので、プログラマーでなくても覚えておいて損はない手段だと思います。

## 手順1: 対象を画面に出しきる

まずChromeでFeedlyにログインし、Read Laterを開きます。

いわゆる無限スクロールなので、下にスクロールすると過去の記事が追加で読み込まれます。抜き出したい期間まで、スペースバーを連打するなどして画面に表示させておきます。私は過去1年分を対象にしました。

DOM上に存在しないものは取り出せないので、この「出しきる」工程が前提になります。

## 手順2: コンソールでDOMを畳んでクリップボードへ

DevToolsを開き、Consoleに以下のスクリプトを貼り付けます。

```javascript
copy(
  ['公開時刻\tURL\tタイトル']
    .concat(
      $$('div.row article').map((article) => {
        const timeSpans = article.querySelectorAll(
          'div.EntryMetadataBasic__source-info span[title]'
        )
        let publishedTime = ''

        // Published: を含む span[title] を探す
        for (const span of timeSpans) {
          if (span.title && span.title.includes('Published:')) {
            let timeStr = span.title
              .replace(/^Published:\s*/, '')
              .replace(/\s*Received:.*$/, '')
              .trim()

            // 24時を00時に変換し、日付を1日進める
            if (timeStr && timeStr.includes(' 24:')) {
              timeStr = timeStr.replace(' 24:', ' 00:')
              const date = new Date(timeStr.replace('GMT+9', '+09:00'))
              date.setDate(date.getDate() + 1)
              publishedTime = format(date)
            } else if (timeStr) {
              publishedTime = format(new Date(timeStr.replace('GMT+9', '+09:00')))
            }
            break
          }
        }

        const link = article.querySelector('a')
        return `${publishedTime}\t${link?.href || ''}\t${link?.textContent?.trim() || ''}`
      })
    )
    .join('\n')
)
```

![Feedlyのリーダー画面とコンソールに貼り付けたJavaScript](https://assets.ideamans.com/miyanaga/images/2025/08/feedly-reader-and-javascript-code.png)

`format()` は `YYYY-MM-DD HH:mm:ss` に整形するだけの関数として別途定義しています。元の実装ではインラインで展開していました。

ポイントは3つあります。

1つ目は `copy()` です。DevToolsコンソール限定のユーティリティで、引数の文字列をそのままクリップボードへ入れてくれます。ファイルに書き出す手間がありません。

2つ目は `$$()` です。これもコンソールのユーティリティで、`querySelectorAll` の結果を配列として返します。そのまま `map()` を繋げられるので、DOMからテキストへ畳む処理が短く書けます。

3つ目は区切り文字にタブを選んでいる点です。CSVだとタイトルに含まれるカンマのエスケープを考える必要がありますが、タブなら記事タイトルに含まれることはまずありません。

:::message
セレクタはそのサービスのDOM構造に強く依存します。ここに挙げた `div.row article` や `EntryMetadataBasic__source-info` は執筆時点のFeedlyの構造に合わせたもので、そのままでは動かない可能性が高いはずです。考え方の型として読んでください。
:::

日付の扱いには少し手こずりました。`Published: ...GMT+9` という形式の `title` 属性から時刻を取り出すのですが、24時表記が混ざっていて、そのままでは `Date` が解釈できません。24時を00時に置き換えて日付を1日進める、という処理を挟んでいます。

## 手順3: 表計算ソフトに貼る

クリップボードに入っているのはタブ区切りのテキストです。ExcelやGoogleスプレッドシートにそのまま貼り付ければ、列に分かれます。公開日時・URL・タイトルの3列が並んだ表になりました。

ここまで来ればあとは自由です。CSVに書き出してもいいですし、そのままAIに読ませることもできます。

## データは誰のものか

Feedlyはお気に入りのサービスで、有料プランも使ってきました。それでも、データの扱いという一点で乗り換えを決めました。

今やどのサービスもAPIを広く公開しています。有料プランでもAPIが使えないというのは、データを人質に取られているような感覚がありました。

AIの活用が進むほど、自分のデータへ自由にアクセスできないことは、サービス提供者と利用者の間に決定的な壁を作ります。エクスポート手段の有無は、機能一覧の片隅ではなく、サービス選定の主要な判断材料になりつつあると感じています。

とはいえ、囲い込まれたデータも画面に出ている限りは手元に取り戻せます。その最後の手段としてDevToolsのコンソールを覚えておくと、乗り換えの決断がしやすくなります。
